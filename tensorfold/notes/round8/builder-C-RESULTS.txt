Texts 15/15 identical in every row. Cause: a kept state is a device copy (110 MiB + ~17 KiB a token = 1.09 GiB at 56K tokens), a request keeps about three
marks, and the cache gets only what the lanes' full-window reservation leaves (28.4 GiB room - 5 x 4.85 GiB). One agent's request fills it and pushes the
others' states out, so every follow-up prefills its whole history again. One user alone is fine (20K system + turns: 0.84 s follow-ups, every turn a hit).
One short prompt on the pool profile: 110.5 ms; cold 7.3K / 29K: 2445 / 2523 tok/s (same as the default profile).

6. DROPPED / NOT BUILT
- TF_FLASHNEXT_Q38_CACHE_SIBLINGS (eviction takes a prompt's own earlier marks first): zero (row 2 of table 5); the store makes room for all of a new request's
  marks at its lookup. Removed from the patch. Upstream's rework is #2699.
- Upstream BF16 128x128 prompt tile (#1846 / #1848, 3.7-4.4 % upstream): not ported. This base's prompt passes already run MiaAI's 128x128 MXFP8 tile
  (TF_FLASHNEXT_PROMPT_MX128 / GEMM2) on the projections; the groups are flat at ~0.36 ms a row and round 7 measured the tensor-core rate equal in every group.
- Upstream KEEP_INPASS as written (#1866) needs its fused DeltaNet kernel's cut; built our own form instead (lever 1).
- Prompt chunk size, expert tile shapes: measured zero in rounds 6-7, not repeated.
